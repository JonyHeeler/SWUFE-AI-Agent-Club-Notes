# 1-3 如何给 AI 提需求

前几年有一个非常火的岗位是提示词工程师，Prompt Engineer。这些人专门为 AI 写提示词，以期得到更好的产出。根据 Lightcast 数据，美国招聘中提及 prompt engineering 的职位从 2023 年约 1400 个涨到 2024 年接近 6300 个。但近些年随着模型的能力越发强大，提示词只要不是特别差，效果就都还 OK，所以这个岗位在一年内迅速消亡。

这一节我们来聊聊如何给 AI 下命令。

“帮我做个好用的抽签器”，表达了愿望，却没有说明什么叫“好用”。AI 可以替你补一些细节，但它补出来的规则不一定适合你的课堂。你需要提出一个需求，才能让你期望的结果和 AI 期望的结果对齐。

## 1. 用五个问题补全需求

| 问题     | 抽签器中的具体答案                 |
| ------ | ------------------------- |
| 给谁用？   | 班会主持人，在自己的电脑上使用           |
| 做什么？   | 从当前名单中随机抽出一人，显示昵称         |
| 输入什么？  | 多行文字，每行一个昵称               |
| 有什么限制？ | 单个 HTML 文件，离线可用，不安装额外依赖   |
| 怎样算完成？ | 空名单有提示；只抽名单内的人；不重复模式抽完后停止 |

总体来说，你要说明**使用对象 + 目标 + 输入与规则 + 限制 + 验收标准**。

一些类似“蓝白配色”“按钮明显”的细颗粒度要求也可以写，但应先说清功能。“高级”“有科技感”等词很难直接验收，最好补上具体要求。

## 2. 给出明确的规则与验收流程

“支持不重复抽取”还不够明确：是同一轮不重复，还是永远不重复？名单改了以后，旧记录怎么处理？

本章采用以下规则：

1. 忽略空行，去掉每行首尾空格，同名昵称只保留一次。
2. 开启“不重复抽取”后，同一轮每个昵称最多抽中一次。
3. 所有人抽完后，显示“本轮已结束”。
4. 点击“重置记录”，或修改名单后，开始新一轮。

对应的验收步骤是：

| 操作                | 预期结果            |
| ----------------- | --------------- |
| 名单只留空行和空格，点击抽签    | 显示提示，不生成名字      |
| 输入“小林、小周、小林”，每行一个 | 去重后按两人处理        |
| 不重复模式下，将两人全部抽完    | 两次结果不同；再点击时提示结束 |
| 点击重置，再次抽签         | 可以重新抽取          |
| 修改名单后抽签           | 只使用新名单，旧记录已清空   |

这类不常发生、却容易出错的情况，叫作**边界情况**。先写出来，开发和检查都会更有针对性。

## 3. 从最小可行产品出发

**MVP（Minimum Viable Product，最小可行产品）**，指的是：用尽量少的功能，做出一个真实可用的初版，拿来验证核心想法。

以课堂抽签器为例：

- **核心需求**：输入名单，随机抽出一人。
- **MVP 功能**：名单输入框、抽签按钮、结果显示。
- **暂缓功能**：登录、多人同步、抽奖动画、导出 Excel。

先让核心流程跑通，再请同学试用，看看它是否解决了实际问题。根据反馈决定下一步要改什么。例如，导入 Excel、登录账号、多人在线等功能，会带来新的文件格式、权限和网络问题。需要先做好核心功能，再考虑要不要加这些。

每次只加一个改进，例如“结果出现时加一个短动画”。改完以后，重新检查抽取和重置，确认新功能没有影响原来的规则。这叫**回归检查**。

## 4. AI 会写代码，为什么还要学技术？

#### 1. 判断代码优劣

AI 给出一个小网站，它的页面能打开、能显示名字，只说明它“看起来能用”，不一定符合抽签规则。如果要求“不重复抽取”，就要检查：同一轮里会不会抽到重复的人？所有人都抽过之后，会不会提示本轮结束？点击重置后，能不能重新抽取？写代码前把这些检查标准列出来，完成后逐项操作。这样才能知道工具是否真正满足需求。

这是功能性的问题。

同时，AI 给你写的代码是否符合工程规范？未来是否可以拓展？你的队友能不能快速上手一起工作？

这是更高层次的问题。我们日后再聊。

#### 2. 把问题说清楚

只说“抽签器坏了”，AI 不知道你当时输入了什么、你做了什么，也不知道本来应该出现什么结果。

可以按这个顺序描述：

- **输入**：名单里写了“小林”和“小周”。
- **操作**：开启“不重复抽取”，连续抽三次。
- **预期**：前两次抽出不同的人，第三次提示本轮结束。
- **实际**：第三次又抽到了小林。

这样，AI 就能照着步骤重现问题，再着手排查。当然，也可以附上报错原文。

#### 3. 知道改动会影响什么

网页的不同部分各有分工：

| 部分         | 主要负责什么   | 抽签器中的例子         |
| ---------- | -------- | --------------- |
| HTML       | 页面上有哪些内容 | 名单输入框、抽签按钮、结果区域 |
| CSS        | 内容怎样显示   | 按钮颜色、字号、页面布局    |
| JavaScript | 操作后发生什么  | 随机抽取、避免重复、记录结果  |

修改一部分，可能会导致其他部分出问题。这很令人恼火。

### 4. 把任务合理拆解

先做一个只在自己电脑上使用的抽签器，名单保存在当前页面里，通常不需要后端或数据库。

如果以后要让多个同学共享名单、登录后查看记录，或关掉网页后仍然保存数据，就需要考虑后端和数据存储。如果工具要查询实时天气或使用在线 AI 服务，则需要联网。

先完成核心功能，再按实际需要增加保存、协作或联网能力。这样更容易发现问题，也不会一开始就处理暂时用不上的复杂功能。

**如果你有想法，其实不必先学完所有编程语法再开始。你可以借助 AI 写出第一个工具，同时逐步弄懂它的输入、规则和运行方式，并学会检查结果。**
