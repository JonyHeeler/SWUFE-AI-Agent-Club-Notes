# 1-5 API、Token、上下文与密钥

使用 AI 工具时，经常会遇到 API、Token、Context、API Key。我们来看看这些内容。

## 1. API：程序之间约定好的接口

API 的全称是 Application Programming Interface，中文通常叫“应用程序编程接口”。它规定一个程序怎样使用另一个程序提供的能力。

以网络服务为例，一次调用通常包括：

```text
你的程序 → 按规定发送请求 → 提供服务的程序
你的程序 ← 收到结果或错误 ← 提供服务的程序
```

假设有一个返回问候语的接口，请求和响应可能长这样：

```json
{ "name": "小林" }
```

```json
{ "message": "你好，小林！" }
```

这里的 JSON 是一种组织数据的文本格式，常用键和值表达信息。你以后会经常遇到它。

真正接入 API 时，要先阅读 API 文档，确认地址、参数、身份验证、返回格式与错误处理。如果你看不懂也可以让 AI 代劳。

API 也可以是软件库或操作系统的接口，**不一定经过互联网**。

## 2. Token：模型处理文本的单位

还记得大语言模型是怎么工作的吗？它预测下一个“词元”。

模型通常先把文字转换为 Token，再进行处理。Token 可能对应一个字、一个词、词的一部分或标点；具体拆分由模型使用的分词方式决定。

**一个中文字不固定等于一个 Token，一个英文单词也不固定等于一个 Token。** 

在常见文本服务中，输入和输出都会产生 Token 用量。输入不只有你最后问的那句话，还可能包含系统说明、对话历史、工具结果和提供给模型的文件内容。

本章只需要理解：不相关材料过多，会占用处理空间，也可能增加耗时与用量。

## 3. Context：本次回答能参考的信息

Context 通常译作“上下文”。它是模型本次生成时能够参考的材料，例如当前任务、保留的对话、代码片段和工具读取的文件内容。上下文窗口有容量限制。长对话或大文件可能被筛选、截取或摘要。因此，重要要求应写清楚，关键材料应明确提供。

比较下面两种求助方式：

> 修一下。

> 请阅读当前文件夹的 index.html。名单为空时，点击“开始抽签”没有提示；预期应显示“请先输入名单”。只修复这个问题，保留其他功能。完成后说明如何验证。

后者明确了文件、触发条件、实际问题、预期结果和修改范围，更容易定位。

## 4. API Key：调用服务的凭据

如果你想在你的软件中调用市场上的大模型，你需要付费。API Key 好比银行卡，它通常用于验证调用 API 的人的身份，可能关联账户费用和访问权限。

- 不把真实密钥放进截图、群聊或公开仓库。
- 不写进发给别人的前端 HTML、CSS 或 JavaScript。
- 怀疑泄露时，在服务管理页面撤销并更换。否则可能有财产损失。

浏览器需要拿到前端代码才能运行页面，别人也能查看这些代码。把密钥藏在变量里、换个名字或压缩代码，都不能可靠保密。需要接入收费服务时，应采用服务提供方支持的安全方案。
