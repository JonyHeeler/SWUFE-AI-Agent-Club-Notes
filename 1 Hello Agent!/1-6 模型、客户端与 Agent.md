# 1-6 模型、客户端与 Agent

## 1. 理清概念

| 概念          | 主要职责                                            | 需要看什么                |
| ----------- | ----------------------------------------------- | -------------------- |
| 模型（Model）   | 根据输入理解、推理和生成内容。例如 `Deepseek V4.1 Flash` 就是一个模型。 | 对具体任务的完成质量           |
| 客户端（Client） | 提供操作界面，组织输入并展示输出；也可能管理工具和权限。                    | 能否读文件、运行工具、查看产物      |
| 智能体（Agent）  | 围绕目标组织步骤，调用工具，再根据结果调整行动                         | 工具是否合适、操作是否正确、任务是否完成 |

本章讨论的是以大语言模型为核心的 Agent。

## 2. Agent 怎样推进任务？

以“创建一个课堂抽签器”为例：

```text
明确目标和限制
      ↓
观察：读取工作文件夹与已有文件
      ↓
规划：确定需要创建或修改什么
      ↓
行动：调用工具写入 index.html
      ↓
读取结果：文件是否成功保存？检查发现了什么？
      ↓
调整：修复问题、继续检查，或完成并汇报
```

这个过程可能循环多次，也可能在简单任务中只经历几步。检查失败时应根据原因修改；条件满足后停止。遇到无法继续的权限或信息问题，Agent 会对你说明具体阻碍，请求你的意见与批准。

## 3. 工具调用：模型提出请求，运行环境执行

模型需要通过应用提供的工具完成操作。可以把一次工具调用理解成：

1. 模型提出结构化请求，例如“列出课堂文件夹”。
2. 客户端或运行环境检查工具是否存在、权限是否允许，并按规则执行。
3. 工具读取文件系统，返回结果或错误。
4. 模型读取结果，决定下一步。

因此，Agent 能做什么，取决于**模型能力、可用工具、环境状态和权限范围**。

## 4. Prompt：把任务说明写清楚

Prompt 通常指交给模型的提示或任务说明。有效提示词没有固定咒语，重点是提供执行所需的信息。下面是一种模板：

```text
目标：创建一个课堂抽签器。
输入：每行一个昵称，忽略空行并去重。
规则：每次抽一人，默认同一轮不重复。
范围：只在当前课堂文件夹内创建 index.html。
限制：单文件、离线可用，不接外部 API。
验收：空名单提示；两人抽完后停止；重置后可再抽。
交付：给出文件位置、打开方式和实际检查结果。
```

你应该定制你自己的 prompt。例如：如果已经有文件，你应该说明“先阅读现有文件，保留已有功能”；如果只是修复一个问题，就把复现步骤和预期结果一起写进去。

## 5. 幻觉：看起来合理，仍可能没有依据

**大模型幻觉**，指模型生成了看似合理、表达流畅，但实际没有事实依据或内容有误的回答。

比如你问某篇论文的结论，模型可能给出一个听起来可信的结论，甚至列出作者、年份和链接；但论文可能不存在，或原文并没有这个结论。

出现幻觉，不是模型“故意说谎”。模型主要根据输入和上下文生成内容，并不天然保证每句话都经过事实核查。问题描述不清、缺少必要材料，或者模型面对它不熟悉的内容时，都可能增加出错的机会。

前几年大模型的幻觉尤其严重。众多工程师做了大量的工作去“反幻觉”，包括优化模型、强制模型联网搜索、不乱说话等等。但即使这样，大模型也会出错，并且会经常出错。遇到重要信息，可以这样核对：

- **查事实**：打开原始论文、官方文档或数据来源，核对原文和日期。
- **查代码**：实际运行一下，检查输入、输出和边界情况。
- **查操作**：确认文件确实写入了指定位置，功能也能正常使用。
- **查不确定处**：让模型区分已知信息和推测，并指出需要核实的内容。
